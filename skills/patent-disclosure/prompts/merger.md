# 迭代模式：增量合并（修订与补充）

## 执行门禁（优先执行，不可跳过）

1. **`Read`** `prompts/iteration_context.md`
2. **`Read`** 用户给出的**当前定稿** `.md`（及本轮 @ 的补充材料）
3. **落盘**：合并结果写入**新文件** `{案件名}_{YYYYMMDDHHmmss}.md` 及同名 `.docx`（见 `references/delivery-naming.md`）。**禁止覆盖**旧稿（除非用户明确要求）

**禁止**：迭代意图下跑 convert 全文或仅「更新分析」而不落盘新时间戳文件。

## 何时启用

用户在**已有交底书**上补充新材料、扩展章节、合并新文档/片段，或按 `draft.md` §交付交互 要求**第五章权利要求书式强化**时执行。**不要求**用户说「迭代」。

## 流程

1. **识别增量**：新内容影响哪些章节（背景、1.1、3.4、实施例等）
2. **非破坏性合并**：以追加或局部重写为主
3. **查新联动**：若增量改变技术实质，补充 **search** 并更新 1.1
4. **脱敏**：合并后按 `references/desensitization.md` 检查新增内容
5. **一致性**：核对 `references/disclosure-checklist.md`；涉及公式时同步 3.4.1 / 3.5 / 第六章
6. **落盘** + **对话记录**：`tools/iteration_dialog_log.py --kind merge`

## 输出（强制）

交付后**必须在同一条回复中**追加：

## 合并摘要（留档）

其下 **3–6 句中文**：改了哪些章节、原因、是否影响保护点或检索、是否已自检。

若本轮为定稿交付，还须按 `draft.md` §交付交互 附「权利要求偏向点」引导（仅对话，不入正文；选项须来自稿内已有论述）。

## 与纠正的区别

- **merger**：新材料、新功能的**扩展**
- **correction_handler**：**错误、与事实不符**的修正
