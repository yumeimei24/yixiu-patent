# 迭代上下文（进入 merger / correction 前必读）

## 本文作用

约定**迭代时先干什么、产出什么**，避免 Agent 只输出分析段落而不落盘新稿，或错误回到 convert/draft 全流程。

## 何时读本文

用户明显在**已有交底书或上一轮交付稿**上继续工作时（补材料、改章节、纠错、调保护点表述等），在 **`Read` `merger.md` 或 `correction_handler.md` 之前**先读本文。

| 意图 | 下一步模板 |
|------|------------|
| 补充文档、扩展方案、合并新材料 | `merger.md` |
| 指出错误、与事实/参数不符、风格或保护点调整 | `correction_handler.md` |
| 用户要求第五章「权利要求书式」强化（须与稿内已有保护点一致，禁止编造新场景） | `merger.md`（以第五章为主） |

## 输入与输出

**输入**

- 对话中的本轮说明；用户 @ 的文件或粘贴片段
- **`Read`** 当前基准交底书 `.md`（用户路径或对话中最新交付稿）

**输出**

- 合并或纠正后的全文写入**新文件**（命名见 `references/delivery-naming.md`）
- 同步生成同名 `.docx`
- 旧版保留同目录，便于对照

### 修订对话记录（必做）

每完成一轮合并或纠正并落盘新 `.md`/`.docx` 后，须在**案件产出目录**维护：

- **文件名**：`交底书修订对话记录.md`（英文环境可用 `disclosure_revision_log.md`）

**每条记录须含**：

1. **记录时间**：本地时间 + UTC
2. **类型**：合并迭代 / 纠正迭代
3. **用户说明摘要**
4. **本轮交付文件**：新时间戳 `.md`、`.docx` 文件名
5. **合并/纠正摘要摘录**

**推荐命令**：

```bash
python3 ${SKILL_DIR}/tools/iteration_dialog_log.py \
  --case-dir "{案件目录}" \
  --kind merge \
  --user "{用户说明摘要}" \
  --summary "{摘要摘录}" \
  --artifacts "{案件名_时间戳.md},{案件名_时间戳.docx}"
```

`--kind correct` 用于纠正迭代。无法执行脚本时，**Read** 已有日志（无则 **Write** 创建），在文末**追加**结构相同的一条。

**禁止**：完成迭代交付却完全不更新对话记录文件。

## 建议执行顺序

1. 读本文 → 选 `merger.md` 或 `correction_handler.md` 并 **Read**
2. **Read** 基准稿 + 本轮补充材料
3. 完成合并或纠正（自检见 `references/disclosure-checklist.md`）
4. **Write** 新时间戳 `.md` → **export** 生成 `.docx`
5. 追加 **`交底书修订对话记录.md`**
6. 回复中写明新文件路径，并输出 **「合并摘要（留档）」** 或 **「纠正摘要（留档）」**

## 禁止

- 已判定迭代意图时，不经合并/纠正、不写入新时间戳文件，却去跑全文 convert 或仅输出分析
- 例外：用户**明确要求**「重新挖掘 / 从头查新 / 重写交底书」
