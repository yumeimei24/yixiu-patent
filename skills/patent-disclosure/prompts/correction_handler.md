# 迭代模式：对话纠正

## 执行门禁

与 `merger.md` 相同：先 **`Read`** `prompts/iteration_context.md`，再 **Read** 当前定稿；纠正结果**另存** `{案件名}_{YYYYMMDDHHmmss}.md` 及同名 `.docx`。**禁止**默认覆盖旧稿。

## 何时启用

用户针对**已有交底书**指出错误、参数不一致、表述问题、保护点调整等时执行。**不要求**用户说「迭代」。

## 步骤

1. **提取纠正点**：章节、原问题、用户期望
2. **分类**：
   - **事实与技术** → 改第三章、实施例、3.5
   - **符号与公式** → 改 3.4.1、3.5 符号列、第六章；全文同形
   - **查新与区别** → 改第一章；必要时 **search**
   - **保护点与表述** → 改第四、五章，与第三章对齐
3. **落地修改**：写入**新时间戳文件**；勿无必要大段重写无关章节
4. **脱敏**：按 `references/desensitization.md` 复核修改处
5. **自检**：`references/disclosure-checklist.md`
6. **对话记录**：`tools/iteration_dialog_log.py --kind correct`

## 输出（强制）

## 纠正摘要（留档）

其下 **2–5 句中文**：修改位置、依据、是否影响保护点或检索。

定稿交付时附 `draft.md` §交付交互 的「权利要求偏向点」引导（缩写即可；禁止编造稿外偏向）。
