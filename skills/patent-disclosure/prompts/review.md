# 创意可专利性审核（review）

## 执行前（必做）

1. **`Read`** `${SKILL_DIR}/references/regulatory-standards.md`
2. **`Read`** `${SKILL_DIR}/prompts/standards_lookup.md` 并 **WebSearch**（至少：专利法第25条 + 用户技术领域；软件/AI 另查计算机程序审查规定）
3. **`Read`** `${SKILL_DIR}/references/patentability-criteria.md`

## 输入

- 用户创意描述、技术方案摘要、原型说明、或已有材料路径
- 可选：目标国家/地区（默认中国发明专利）

## 输出结构

向用户交付 **《可专利性初步评估报告》**（Markdown），包含：

### 1. 方案概要

3–5 句复述用户方案（不添加用户未述及的技术细节）。

### 2. 保护客体初判

- 是否属于专利法排除客体（科学发现、智力活动规则、疾病诊断治疗方法纯呈现等）
- 建议保护形式：方法 / 系统 / 装置 / 存储介质 / 组合

### 3. 三要素闭环

| 维度 | 内容 |
|------|------|
| 区别点 | 与常规做法的差异步骤或结构 |
| 技术问题 | 该差异针对的问题 |
| 技术效果 | 可预期的技术效果（避免纯商业效果） |

若任一项无法从材料中提炼，列为 **「待用户补充」** 并给出具体问题。

### 4. 新颖性 / 创造性 / 充分公开 初判

每项：**初步结论**（高/中/低 风险或信息不足）+ **理由** + **建议补充材料**。

不做法律定论；明确写「需代理师结合检索报告确认」。

### 6. 规范依据摘要

列出本轮 WebSearch 采用的**权威来源 URL**（1–5 条）及与本案相关的硬性约束摘要。

### 7. 查新建议

列出 3–6 个建议检索词块；若用户同意，转入 **`prompts/search.md`** 执行查新。

### 8. 总体建议

- **建议申请** / **建议补充后再评估** / **不建议申请（说明理由）**
- 下一步：进入 convert / search / draft 等

## 禁止

- 不编造用户未提供的实施细节以「凑」可专利性
- 不输出正式法律意见或授权概率百分比
