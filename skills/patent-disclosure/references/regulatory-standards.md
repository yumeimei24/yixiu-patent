# 专利创意与撰写技术规范（约束基线）

> 本文件为 skill **硬性约束基线**，来源于《专利法》（2020 修正）、《专利审查指南》（2023 修订精神）及国知局公开业务提醒。  
> **执行 review / draft / upgrade 前必须 Read 本文件**；并依 `prompts/standards_lookup.md` **WebSearch 核验**最新领域要求。

## 一、可专利性（创意审核约束）

### 1.1 法定三性（专利法第 22 条）

| 要件 | 约束要点 | 来源 |
|------|----------|------|
| **新颖性** | 不属于现有技术；无抵触申请 | [专利法第22条](https://www.cnipa.gov.cn/art/2020/11/23/art_97_155167.html) |
| **创造性** | 发明：相对现有技术**突出的实质性特点** + **显著的进步** | 同上；《审查指南》第二部分第四章 |
| **实用性** | 能够制造或使用，并能产生**积极效果** | 同上 |

**现有技术**：申请日（有优先权则优先权日）以前**公众可得**的技术（出版物、公开使用等）。

**创造性审查参考**：最接近现有技术 → 区别特征 → 实际解决的技术问题 → 是否显而易见（三步法）。

### 1.2 不授予专利权客体（专利法第 25 条）

下列情形**不得**按可专利发明推进撰写（须 review 阶段明确指出）：

1. 科学发现  
2. **智力活动的规则和方法**（纯规则、纯算法、纯商业方法且无技术特征）  
3. 疾病的诊断和治疗方法  
4. 动物和植物品种（生产方法除外）  
5. 原子核变换方法及所获物质  
6. 主要起标识作用的平面印刷品设计  

**软件/AI 特别规则**：权利要求若**除主题名称外均为**算法或商业规则特征 → 属第 25 条(2)；若**整体含技术特征**且通过技术手段解决技术问题并产生技术效果 → 不应仅依第 25 条排除，再审查是否属技术方案（审查指南第二部分第九章）。

### 1.3 技术方案（专利法第 2 条）

技术方案是对**技术问题**采用**技术手段**并产生**技术效果**的集合。创意审核须检验：

- 是否有具体技术手段（非纯思维规则）  
- 是否解决可界定技术问题（非纯商业目标）  
- 是否可预期技术效果（可验证、可实施）

## 二、技术交底书撰写约束

交底书为**内部技术说明**，支撑代理人撰写申请文件；结构应使代理人能实施理解。

### 2.1 推荐模块（与审查指南说明书结构对应）

| 模块 | 约束 |
|------|------|
| **名称** | 通用技术术语；简明全面；**建议 ≤25 字** |
| **技术领域** | 所属及直接应用的具体领域；先宽后窄 |
| **背景技术** | 最接近现有技术 + 客观缺点；**围绕技术内容**；注明出处/检索线索 |
| **发明内容** | **技术问题 + 技术方案 + 有益效果** 三位一体 |
| **附图说明** | 有图则逐幅说明；实用新型必须有附图 |
| **具体实施方式** | 足够详细、可实施；必要时实施例与参数 |

### 2.2 国知局撰写提醒（2025）

- 申请文件核心为**技术方案**，避免无关内容（尤其背景技术、附图）
- 背景技术缺点应围绕**技术**，避免政治、经济、文化等与技术无直接关系的信息
- 说明书：**用词规范、语句清楚**；不得使用「如权利要求……所述的……」；不得商业性宣传用语

来源：国知局《进一步规范专利申请文件撰写要求》业务提醒（2025-04）。

### 2.3 本 skill 交底书额外红线

- 三要素闭环：区别点 → 技术问题 → 技术效果  
- 1.1 现有技术条目须含**可核验 URL**（查新后）  
- 脱敏成稿：见 `desensitization.md`  
- 禁止论文腔、禁止编造源材料外技术特征

## 三、发明专利申请书撰写约束

### 3.1 说明书（审查指南 第二部分 第二章 2.2）

**组成部分及顺序**（标题除外）：

1. 技术领域  
2. 背景技术（对理解、检索、审查有用；可引证背景技术文件）  
3. 发明内容（技术问题、技术方案、有益效果）  
4. 附图说明  
5. 具体实施方式（优选实施方式；有附图则对照说明）

### 3.2 权利要求书（审查指南 + 团体规范摘要）

**形式**：

- 阿拉伯数字顺序编号；编号前**不得**冠以「权利要求」「权项」  
- **不得有插图**；可以有化学式、数学式；必要时表格  
- **每一项仅结尾一个句号**；中间用分号、逗号  

**实质**：

- 以说明书为依据；清楚、简要地限定保护范围（专利法第 26 条第 4 款）  
- 至少一项独立权利要求  
- 独立权利要求：前序部分 + 「**其特征在于**」+ 特征部分（方法/系统体例见 `claims-rules.md`）

**禁止用语**（权利要求中不应出现，除非领域公认明确含义）：

`等`、`约`、`大约`、`可能`、`也许`、`例如`、`比如`、`优选`、`可以`、`不限于`、`基本`、`接近`、`左右`、`必要时`、`尤其是`、`或类似物`、`某种程度上`

以及：**商品名称、商标、公司名称、产品型号、商业宣传用语**

**不宜绝对化**：`仅`、`所有`、`全部`、`必须`、`一定不` 等（除非技术确需）

参考：T/CIPSA 0007-2024《专利申请文本撰写规范》5.3.1；与审查指南冲突以审查指南为准。

### 3.3 说明书摘要

- **不超过 300 字**  
- 名称与请求书/权利要求一致  
- 技术问题、方案要点、主要效果

## 四、创意审核输出须对照的检查表

review 模式交付前，逐项标注 **符合 / 风险 / 信息不足**：

```
□ 是否属于专利法第 25 条排除客体？
□ 是否具备技术方案三要素（手段-问题-效果）？
□ 新颖性：是否有明显公开文献/产品风险（结合 search）？
□ 创造性：区别特征是否可能被视为常规组合或显而易见？
□ 实用性：能否制造/使用、有无积极效果？
□ 充分公开：材料是否足以支撑具体实施方式？
□ 软件/AI：是否含必要技术特征（非纯算法/纯商业规则）？
```
