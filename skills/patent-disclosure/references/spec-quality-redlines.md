# 说明书质量红线（十类高频缺陷与修法）

> 案件来源：2026-10-14 两份多模态识别/预警类说明书复盘（缺陷全部来自真实成稿，已脱敏）。
> 用法：draft / upgrade 撰写时对照第 1–10 节的"修法"；定稿前用 `tools/consistency_scan.py` 机械扫查（第 11 节）。
> 本文件与 `output-layout-style.md` §4、`implementation-writing.md` §6 配套：那边管"怎么写好"，这边管"什么写法直接判退"。

---

## 1. 公式引导句空悬

**现象**：正文写"公式如下表示："（或"计算公式为：/表示如下："），下一行直接是"其中，…"——公式本体缺失。
**真实例子**（脱敏）："通过如下的公式加权生成多模态数据的时空特征O：" → 紧跟"其中，ε为用于防止涂零的参数…"。更严重的成稿里出现孤立的一行"。"。
**错因**：公式写在 Word 公式对象（OMML）里，或者撰写时先写了引导句没填公式；回读校验只看文字，看不出公式对象是否为空。
**修法**：
- 公式一律写在源稿 `$$…$$` 独立成行（md_to_docx_min.py 会渲染为居中公式段），**不依赖 Word 公式对象**；
- "其中，…"句**必须**出现在公式行之后，且中间不得插入其他段落；
- 定稿回读（extract_docx_text.py）后，逐一核对每条"公式如下/计算公式为"引导句的下一段是公式内容，孤立标点行（单独一行"。"或"；"）一律删除。

## 2. 公式无编号、符号重定义

**现象**：公式无 (1)(2)…编号；同一符号在两处定义为不同含义。
**真实例子**（脱敏）：同一特征符号 Y_RGB 在模块一定义为"初始特征"、在模块四又定义为"精炼前景特征"；α 同时用作"宽高比一致性权重因子"与另一处的可学习融合权重；σ 既当高斯分量方差又当坐标不确定性。
**错因**：边写边起名，没有先建符号表。
**修法**：
- 每个公式独立成行并按出现顺序编号（式(1)…(N)），编号置于式后全角空格+（N）；
- 动笔前先建**符号表**（符号 | 含义 | 首现位置 | 取值域），符号一经定义全文不得重定义、不得复用；新增含义必须起新符号；
- 两个符号若只差下标（如 σ_x 与 σ_k），在符号表分两行列清，含义不得混淆。

## 3. 术语漂移（同一对象多名、英文大小写不统一）

**现象**：同一模块在权利要求、发明内容、实施方式、附图说明中名字不同；英文技术名大小写/拼写前后不一。
**真实例子**（脱敏）：某特征提取模块在权利要求中叫"特征提取模块"，实施方式中先后叫"感知解耦抗噪特征提取模块""模态解耦抗噪特征提取模块"，附图说明中叫"模态解耦抗噪特征提取模块流程图"，融合模块也被中途改称"对抗域不变多维协同融合模块"；"TimeSformer/Timesformer/timeSformer"三写混用。
**错因**：改稿时只改了一处名称；无术语清单。
**修法**：
- 动笔前建**模块名清单**（系统组成每个模块的法定名），全文（含附图说明、附图节点）只准使用清单名；
- 英文名首次出现给"中文（English Name, Abbr）"，此后只用同一大小写拼法；
- 定稿用 `tools/consistency_scan.py` 的模块名变体扫查核对（它会把"XX模块/单元/网络/编码器"类名词短语聚类，报出互为变体的对与行号）。

## 4. 错别字成窝与双标点

**现象**：高频错字反复出现；双标点（，，/。。/；；）残留。
**真实例子**（脱敏）："长时续依赖"（应为"长时序依赖"，连错 4 次）、"防止涂零"（应为"除零"）、"每一个相像素点"、"时间序列IMU的的互补性特征"、"ReLu"（应为 ReLU）、"Min-MAX归一化"、"，，因此需要"、"深度信息Depth的精炼前景特征YIMU"（标签抄错：YIMU 前冠了 Depth）。
**错因**：AI 生成后无逐句校对；复制粘贴时上下行标签错位。
**修法**：
- 定稿跑 `tools/consistency_scan.py`（内置错字黑名单 + 双标点扫查），逐条修；
- 复制模块定义到实施例时，逐行核对"模态名 + 特征符号"配对（标签错位是复制粘贴最高发错误）。

## 5. 权利要求用语混入说明书

**现象**：说明书正文出现"其特征在于"，自称"本专利"。
**真实例子**（脱敏）："一种计算机程序产品，包括计算机程序/指令，其特征在于，所述计算机程序/指令被处理器执行时实现…"出现在具体实施方式；实施方式里写"本专利提出的…系统"。
**错因**：把权利要求书文本原样搬进说明书。
**修法**：
- 说明书全文（含发明内容、实施方式）禁用"其特征在于"——该措辞只属于权利要求书；
- 自称统一为"本发明"（引述申请阶段语境可用"本申请"），全文不出现"本专利"；
- 说明书发明内容写程序产品客体时用"本发明还提供一种计算机程序产品，包括计算机程序，所述计算机程序被处理器执行时实现…"。

## 6. 实施例复制发明内容（信息零增量）

**现象**：具体实施方式把发明内容的模块定义整段复制一遍，实施例只有权利要求式复述，无任何新增信息。
**真实例子**（脱敏）：实施例1 先复制系统组成三段（每段 300+ 字），再逐模块"进一步地"重复同一套流程，全文重复率过半。
**错因**：把"具体实施方式"当作"发明内容的扩写"而不是"可复现的实施"。
**修法**：
- 按 `implementation-writing.md` 的 10 段骨架写：总起段 → 对象与数据界定 → **参数配置表** → 逐步骤细节（处理对象/触发条件/过程/输出）→ 结果呈现（精确数字）→ 对照/验证 → 替代实施方式（编号列举）→ 系统/设备/介质实施例 → 收尾句；
- 实施例相对发明内容**必须**新增：参数取值、数值例子（用实际数字走一遍公式）、对照数据、步骤细化（二级编号）——四者至少有其二；
- 发明内容与实施方式禁止出现逐字重复的 200 字以上段落。

## 7. AI 腔句式与形容词效果

**现象**：开头三段全是"随着…飞速发展/日益迫切"；每段结尾"显著提升/有效解决"；"研究表明"无引证；名词化堆叠；自我表扬段。
**真实例子**（脱敏）："实现了对环境噪声深度解耦，跨域对抗鲁棒学习和预测性决策闭环"；"研究表明，具备…能力的目标识别技术具有广阔的市场需求和应用前景"；"此步骤的多高斯混合模型核心优势在于…"；"并非简单集成多个深度模块，而是基于场景感知设计，系统性地引入注意力机制"。
**错因**：把论文摘要腔与营销腔带进法定文本。
**修法**：
- 禁词/禁句式清单（见 `output-layout-style.md` §4 与下方）：飞速发展、日益迫切、亟待解决、关键技术难题、广阔的市场需求、应用前景（除非引证市场报告并给出处）、极大地、真正实现、首次、领先、SOTA、赋能、底座、闭环生态、"研究表明"（无引证）、"核心优势在于"；
- 优点/效果句必须是**因果三段**：因（技术特征）→ 果（可测效果）→ 据（数字或机理）；无数据时写机理，禁写"显著/大幅/有效"；
- 说明书开头背景技术段禁用"随着…的发展"起句，直接写技术问题与现有技术；
- 删掉一切"此步骤能够/此方法可以在"式自我评价段——模块的作用写在模块定义里，效果写在有益效果里，且带证据。

## 8. 无源量化数字

**现象**：效果句里的精确数字无出处、无条件、无对照。
**真实例子**（脱敏）："小波变换能够准确识别95%以上的环境突变事件，让系统能提前200ms做出响应调整"——95% 与 200ms 无任何实验条件支撑。
**错因**：为了让效果"显得可信"而填数。
**修法**：
- 文中每个百分数/毫秒/倍数必须可追溯到源材料（交底书实验、引证文献、设定值），否则改为机理描述或标【待补充】；
- 条件性数字必须带前提（"例如，N=10，对应200ms"须先写明帧率 50fps）；
- 提醒自己：**编造的效果数字在审查与无效程序中比没有数字更危险**。

## 9. 背景技术评述失焦、引证句重复

**现象**：引证一件现有技术后，缺点评述绕回自身、重复啰嗦；句子带双标点。
**真实例子**（脱敏）："不过该专利对于强光、背景运动等动态复杂环境的抗干扰问题没有详细研究，未考虑到外界因素的干扰。但是对于动态目标识别问题，复杂背景干扰的处理亦尤为重要，，因此需要对其进行专门处理…"——"未考虑外界因素"与"抗干扰问题没有详细研究"同义反复，且"，，"残留。
**错法**：
- 每件现有技术的评述固定三句：方案要点（做了什么）→ 客观缺点（技术缺点，一句）→ 与本案的关系（本案在哪一步解决它）；不写第四句；
- 一件现有技术评述段 ≤ 6 行；缺点不重复；
- 评述缺点**围绕技术**，不写"未考虑到外界因素"这类空话，写具体技术缺陷（如"其损失函数未包含时序一致性项，相邻帧预测框无平滑约束，长序列跟踪出现漂移"）。

## 10. 附图说明与正文引用脱节

**现象**：附图说明列了图N，正文无"如图N所示"；或正文引用的图名与附图说明措辞不一致。
**修法**：
- 按 `implementation-writing.md` §3 附图引用规则：每张附图在实施方式中至少一次"如图N所示/参见图N"；
- 位置：总流程图→实施例总起段；框图→对应步骤展开段开头；子流程图→该机制首次展开处；
- 写完后对照附图说明逐图检查引用（工具会报未引用的图号）。

## 11. 机械扫查（定稿必跑）

```bash
python <skill>/tools/consistency_scan.py <file.md>              # 全部检查，报告
python <skill>/tools/consistency_scan.py <file.md> --strict     # 有告警即退出码 1
```

覆盖：双标点、错字黑名单、术语变体聚类（模块名多名）、公式引导句空悬、孤立标点行、符号重定义、权利要求用语混入（"其特征在于"）、无源量化效果句、禁词表。
纯标准库、离线可用。报告为分级：[ERROR] 必修，[WARN] 逐条确认。
