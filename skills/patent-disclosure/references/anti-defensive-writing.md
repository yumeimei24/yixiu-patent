# 防御性写作红线（交底书是技术主张书，不是自我审查报告）

> 来源：2026-10-18 案件复盘。触发事实：用户直接判定某稿"文本写的真心不行"——满篇"可选地/在需要控制时/本步骤的作用是"、效果只给区间、把方法互相矛盾的证据原样写进效果段。学习来源（GitHub 公开 skill，MIT/同名原则）：
> - Adkid-Zephyr/anti-defensive-writing-Skill（发布会原则：识别最值得主张的价值，围绕它组织全部材料）
> - Boom5426/Nature-Paper-Skills 的 anti-defensive-writing（六种声音识别与"必须保留"清单）
> - Smoothsailing0/anti-defensive-writing-skill（中文否定对偶、模板壳的改写实例）
> 已按发明专利场景校准；三份原文不入仓库，仅吸收规则。配套：`consistency_scan.py` 已内置「防御性表达」扫查项。

## 0. 一句话原则

交底书是一场**技术主张**，不是项目总结、实验日志或自我审查报告。你的任务不是平均呈现做过的所有事情，而是识别本方案真正成立、可检验、可主张的价值，围绕它组织全部章节。写每一句前问：**这句话让代理人更想主张，还是替审查员递刀子？**

## 1. 六种声音（识别 → 修法）

| 声音 | 典型线索（交底书场景） | 修法 |
|---|---|---|
| ① 审计腔：过程流水账漏进正文 | "本研究先后尝试了 A、B、C"、"第 X 轮实验中我们发现"、"开发过程中排查了……" | 只写**最终成立的方案**与它的技术事实；过程叙事进`交底书修订对话记录.md`，不进正文 |
| ② 防御腔：对着假想的审查员辩论 | "并不是说……而是……"、"需要说明的是"、"这并不意味着"、"在一定程度上"、"从多个维度综合分析" | 正面陈述对象是什么、方案做什么；真正的限定条件**只写一次、写在起作用的位置、用正面句式** |
| ③ 自我批评腔：替对方完成攻击 | "该方法仍存在不足"、"效果有限"、"未能超过 X"、"遗憾的是"、"仍有待改进" | 改写为**设计决策**（"采用 X，使得……"）或中性事实；真正的边界写一句"适用范围"，不写忏悔段 |
| ④ 评论腔：评判领域、读者或修辞 | "众所周知"、"可以看出"、"毋庸置疑"、设问后自答、空泛展望"为……提供了新思路" | 删；换成它所代表的那个事实陈述 |
| ⑤ 开发者腔：仓库漏进正文 | 脚本名、文件名、目录路径、"运行 config.json"、"脚本输出 saved 到 out/" | 改成读者术语："所述计算机设备读取预设配置"；“参数配置表”承载实现细节 |
| ⑥ 承诺腔：许诺还不存在的东西 | "后续将进一步优化"、"未来版本将支持"、"有望应用于……" | 删；专利文本只写**当下存在且可实施的**方案 |

## 2. 高频模板壳 → 正面改写（对号入座）

| 模板壳（删） | 改成（写） |
|---|---|
| "在需要控制类目规模分布时，（可选地）执行步骤 S7" | "步骤 S7 以仅设下界的容量约束控制类目规模分布。具体为……"（方案即主张，没有"可选"） |
| "并不只是简单聚类，而是……" | 直接写"以……执行聚类，使得……"（比较级修辞零信息） |
| "本步骤的作用是……"（每步都缀） | 作用写进该步骤的处理逻辑本身；确有必要时只在步骤首句用半句带过 |
| "从而解决……的后果"（每点问题都写"后果"） | "从而解决……问题"（"后果"是防御性复写） |
| "归一化互信息由 0.396 提升至 0.454 至 0.471"（效果只给区间） | 挑**主结果**给点值并给对照口径："由 0.396 提升至 0.470（对照口径：同语料、同句向量、同评测脚本）" |
| "其在某些平台上低于另一指标口径下的数值"（把矛盾证据写进效果段） | 删；指标口径分歧属于研究报告，不属于主张文本。效果段只放支持主张的对照数据 |
| "需要说明的是，……" | 删掉这七个字，句子照常成立 |
| "在一定程度上受……影响" | 写具体机制："受温度取值影响：温度高于 X 时，软分配熵达最大值的 96.6%" |

## 3. 必须保留（这不是防御，是支撑主张的骨架）

以下内容**永不**因语气直白而删除；它们是"load-bearing"：

1. **技术效果的真实数据与对照口径**（可溯源：同语料、同模型、同评测脚本）；无源数字才要删。
2. **方案成立的边界条件**（温度下限截断、收敛阈值、迭代上限）——写在对应步骤里，一次，正面句式："若温度低于 0.005，按 0.005 截断，以避免数值失稳"。
3. **诚实的现有技术定位**（背景技术引证与"其一…其N"不足）——这是创造性论证的地基，不是示弱。
4. **替代实施方式**（"X 可替换为 Y，替换后仍能实现……，代价是……"）——这是特征储备库，是扩大保护范围的，不是防御。
5. **法定禁区**（"其特征在于"不进说明书、禁宣传用语、禁编造数据）与固定免责声明流程——合规红线高于语气规则。

## 4. 边界（防矫枉过正）

- **语气永不凌驾于证据**：不删数字、不删对照、不删真实边界来换"显得自信"；删的是**复读的免责、空泛的限定、自我否定**。
- **正面改写必须字面为真**：改写后逐句自检"这句话字面成立吗"；不确定的事实宁可标【待补充】，不写没有的。
- **背景技术的"不足"段不适用本红线**：那里需要明确指出 N 点不足——但每点写**技术机制**（为什么发生、导致什么），不写"效果不好"式结论，也不写自我贬低。
- **效果段"其一…其N"与背景"其N"逐点对应**的结构不变；变化只在于每点内部：一个主张 + 一个机理 + 一组对照数据，不夹带反驳与让步。

## 5. 定稿自查（八问）

□ 有没有哪句话在替审查员完成论证？　□ 有没有"需要说明的是"式空壳？　□ 效果段是否只含支持主张的对照数据？　□ 每个步骤是否直接以"动作+对象+条件+输出"展开（无"可选地/在需要时"开头）？　□ 有没有把过程流水账写进正文？　□ 有没有承诺未来工作？　□ 正面改写后的每个数字是否仍可溯源？　□ 全文有没有同一事实的第二次免责？

机械扫查：`python tools/consistency_scan.py <成稿.md>` → 「防御性表达」WARN 逐条处置。
