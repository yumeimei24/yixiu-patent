# 交付文件命名（必遵循）

凡向用户**落盘交付**的技术交底书 `.md` / `.docx`，须遵循本规则（首次定稿与每次迭代相同）。

## 1. 提取案件名

从正文 `**案件名称**：` 行取完整发明名称；去掉占位（`[待填写]`、`【待填写】`）、首尾空格。

## 2. 规范化

- 删除或替换 Windows 非法字符：`\ / : * ? " < > |` 与换行
- 连续空格可压为单个或删去

## 3. 长度

文件名（不含扩展名）建议 **≤ 80 字符**；超长则截断到约 80 字并保留语义（如截在「方法及系统」等结尾词前）。

## 4. 时间戳后缀（凡交付必带）

主文件名：

```text
{规范化案件名}_{YYYYMMDDHHmmss}.md
{规范化案件名}_{YYYYMMDDHHmmss}.docx
```

- `YYYYMMDDHHmmss` 为**落盘时本地时间** 14 位数字（如 `20260703180530`）
- **首次定稿**与**迭代合并/纠正**同一规则
- **禁止覆盖**已有交付文件；每次交付即新时间戳、新文件名（用户明确要求覆盖时从其意）
- 过程性中间稿文件名可自定，**最终交付**不得省略时间戳

## 5. 双格式交付

定稿须**同时**交付 Markdown 与 Word：

```bash
python3 ${SKILL_DIR}/scripts/render_disclosure_docx.py \
  --input "{案件名}_{时间戳}.md" \
  --output "{案件名}_{时间戳}.docx" \
  --base-dir "{案件目录}"
```

Agent 落盘时即采用上述命名，并在回复中写明完整路径。

## 6. 产出目录

默认 `./outputs/{案件标识}/`；用户指定路径时从其指定。`outputs/` 由 `.gitignore` 忽略。

## 7. 例外

- 用户书面指定文件名时从其意（仍建议保留时间戳）
- 仓库内 `examples/` 教学示例可用固定名
