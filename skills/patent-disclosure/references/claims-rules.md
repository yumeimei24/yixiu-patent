# 权利要求与说明书规则

> **法定硬约束**见 `references/regulatory-standards.md` 第三节。  
> **upgrade 前**须 Read 该文件并按 `prompts/standards_lookup.md` WebSearch 核验。

## 权利要求规则

- 发明名称与摘要名称**绝对一致**
- 编号用阿拉伯数字；编号前**不得**冠以「权利要求」「权项」
- 独立权利要求用「**其特征在于**」引出技术特征
- **每一项权利要求仅末尾一个句号**；中间用分号或逗号
- **不得有插图**；可有化学式、数学式；必要时表格
- **禁词**（审查指南 + T/CIPSA 0007-2024 摘要）：等、约、大约、可能、也许、例如、比如、优选、可以、不限于、部分、某些、若干、某种程度上、基本、接近、左右、必要时、尤其是、或类似物
- **禁止**：商品名称、商标、公司名称、产品型号、商业宣传用语
- **不宜绝对化**：仅、所有、全部、必须、一定不（除非技术确需）
- 从属权利要求引用的特征必须在被引权利要求中已有
- 多项从属权利要求不得引用另一多项从属权利要求
- 不得直接粘贴论文章节；改写为步骤化/模块化专利语言

## 独立权利要求示例

**方法**：

```text
1.一种[发明名称]方法，其特征在于，包括：
[步骤A]；
[步骤B]；
[步骤C]。
```

**系统**（源材料支持架构/模块时）：

```text
2.一种[发明名称]系统，其特征在于，包括：
[模块A]，配置为……；
[模块B]，配置为……。
```

## 说明书结构（审查指南 2.2）

- **技术领域**：一句，与摘要领域一致
- **技术背景**：对理解、检索、审查有用的背景；可引证文件；**围绕技术问题**，避免无关政治经济内容
- **发明内容**：技术问题 + 技术方案 + 有益效果
- **附图说明**：每图一句
- **具体实施方式**：优选实施方式；关键步骤答四问：是什么、解决什么、如何操作、达到什么效果

**说明书禁令**：不得使用「如权利要求……所述的……」；不得商业性宣传用语

## 说明书摘要

- ≤300 字
- 格式倾向：【名称】，【领域】，【方案】，【效果】

## 附图规范

- 黑白线条框图或流程图
- 禁止彩色、实物照片

## 常见错误

- 权利要求范围超出源材料支持
- 背景技术问题源材料未识别
- 实施例读像论文翻译
- 附图模块与权利要求不一致
