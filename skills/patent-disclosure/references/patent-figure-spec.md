# 专利附图规范（技术路线图 / 流程图 / 框图）

案件来源：测量类与抽取类交底书案（多案共 8 幅图）后新增；具体案件信息已脱敏。
执行引擎：`paper2patent/scripts/generate_patent_drawings.py`（纯标准库 SVG + Pillow PNG）。

## 1. 法定与撰写规范

- 附图应当用**黑色线条**绘制，不得着色，不得使用工程蓝图、照片；允许流程图、框图、示意图。
- 图内**不得出现图号与图题**（"图1"及其标题写在说明书附图说明与正文，不画进图内）。
- 附图标记：阿拉伯数字；同一部件/步骤在全部附图与正文中使用同一标记；标记不得在图中重复解释。
- 附图中的文字优先使用中文，可含必要英文缩写（首次在正文定义）；文字应打印清晰可读。
- 流程图：起始/结束用圆角框（terminal），处理用矩形（process），判断用菱形（decision）并标"是/否"；循环保留侧向通道。
- 框图（系统/装置）：模块用矩形，模块间关系用带箭头连线；数据流可加注数据名。
- 一幅图表达不下时拆为（a）（b）两幅或在附图说明中说明。

## 2. 引擎输入契约（专利内容 JSON）

```json
{"drawings": [
  {"figure_no": 1, "title": "整体流程示意图", "type": "flowchart",
   "source": "交底书 §详细技术方案 0",
   "nodes": [
     {"id": "S101", "label": "S101 获取招聘岗位文本并预处理"},
     {"id": "S102", "label": "S102 相似度≥阈值？", "shape": "decision"},
     {"id": "OUT",  "label": "输出处理结果", "shape": "terminal", "ref": "E_j"}
   ],
   "edges": [
     {"from": "S101", "to": "S102"},
     {"from": "S102", "to": "OUT", "label": "是"},
     {"from": "S102", "to": "S101", "label": "否", "both": false}
   ]}
]}
```

- `type`：只接受 **`flowchart`**（分层自上而下，标签约 18 字换行）与 **`block`**（系统/结构框图，标签约 12 字换行）两种取值；其它字符串会被引擎拒绝（已核实上游实现）。
- `shape`：`process`（默认矩形）/ `decision`（菱形，判断框）/ `terminal`（圆角，起止）。
- `ref`：附图标记，画在节点框外用引线标出；`label` 内也可直接带标记（如 "S101 …"）。
- `edges[].label`：边上的文字（如"是/否"、"下一轮"）；`both: true` 表示双向箭头。边也可写成数组形式 `["S101","S102"]` 或 `["S101","S102","是"]`。
- `container`：可选**整幅外框** `{label, ref}`（如"××测量装置 300"），它框住该图的**全部**节点，用于装置/系统类附图；不是泳道或分组框，不能只框一部分节点。
- **编号与正文一致**（2026-10-13 案复盘新增）：图1（整体流程）节点编号=正文一级步骤号（交底书 S1—S10 ↔ 节点 S1—S10），不得另造 S101 系列；细化图用图号系列**二级编号**（图2→201…、图3→301…、图4→401…；判断框不带编号），并在实施方式中写明"如图2所示，步骤S2与S3的细化流程包括二级步骤201至209"；进入申请书阶段再按权利要求统一改号。
- **图1线性主流程**（专利通行风格，引自 best-skills figures-drawio.md）：整体流程图只画 S1→SN 线性主线，不画判断框、分支与回边；判断框、回边与闭环放细化图（图2、图4）；上游 checker 的 F10 告警以"任一附图含判断框或环回"满足。图幅告警（字高<2.2mm）时优先减节点/缩短标签，其次拆图。
- **每图至少一次正文引用**：写完实施方式后对照【相关附图】逐图检查"如图N所示/参见图N"各至少一次；总流程图→实施例引导段，子流程图→该机制首次展开处，框图→对应展开段开头。
- 引擎强制规则：只画列出的节点与边；标签换行不截断；节点标签含"图\d"报错；孤立节点警告；节点数 >16 提示拆图；内容区占图幅比例 ≥0.8、打印文字 ≥2.2mm 才算通过。
- 输出：`{prefix}_图{n}.svg` + `.png`（300dpi）；`--update-json` 把 `drawing_assets`（校验结果、路径）写回输入 JSON。

## 3. 图幅清单模板（供直接落规格）

测量类 / 抽取类方法发明的标准四图布局（可直接改写成具体案件的规格）：

- 图1 整体流程（flowchart，**线性主流程**）：S1 … → SN（terminal）；只画主线，不画判断框、分支与回边，机制留在图2、图4。
- 图2 核心机制的细化流程（flowchart，二级步骤201…）：判断框不带编号并标"是/否"；回边必须在正文中有依据。
- 图3 结构 / 网络 / 映射关系示意图（block）：节点用 f1—f6、a1—a5 一类占位标记，边权或关系标注在边上。
- 图4 关键步骤的细化流程（flowchart，二级步骤401…）：循环、终止条件与终点的 terminal 画清楚。

一个可直接跑通引擎的完整四图规格见本仓库 `examples/figures-spec-example.json`
（运行：`python skills/paper2patent/scripts/generate_patent_drawings.py examples/figures-spec-example.json -o examples/out --prefix 示例 --update-json`）。

## 4. 校验清单（每图）

□ 纯黑白、白底；□ 图内无图号/图题；□ 节点编号与正文步骤号一致（图1=S1—SN，细化图=二级编号）且全文同义；□ 只画正文有的节点与边，分支/环回有正文依据；□ 判断框/回边至少出现在一幅附图中（图1线性主线时由细化图满足，否则上游 checker 告警 F10"权利要求含迭代/校验机制但附图无判断框或环回"）；□ 节点 ≤16、标签断行合理、打印字高 ≥2.2mm；□ 内容区占比 ≥0.8（引擎 validation.passes=true）；□ SVG+PNG 双格式成对输出；□ 缩至三分之二仍可辨（打印字高与框内边距的复核标准）；□ **已逐张目视检查 PNG**（模型不能读图时运行 `tools/verify_figures.py`：SVG 标签齐全＋PIL 像素统计，并请用户人工复核）；□ 每图在实施方式中至少一次"如图N所示"引用；□ 附图说明"图N为…"与图一一对应。
