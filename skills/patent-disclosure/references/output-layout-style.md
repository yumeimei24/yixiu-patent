# 输出体裁与版面规范

本文件规定交付文本的**体裁选择**与**版面约定**，适用于 draft / upgrade / export 各模式。
案件来源：2026-10 测量类交底书案（用户要求按团队既往专利初稿的体裁排版）后新增；样稿名称已脱敏。

## 1. 体裁优先级（冲突时按此顺序）

1. **用户提供的样稿**（团队既往专利初稿、已受理申请文本、代理所回稿）——按其**章节结构 + 版面样式**复刻体裁；
2. **机构/代理所交底书模板**（如 AIPO 模版：发明名称 / 所属技术领域 / 背景技术介绍 / 解决的技术问题 / 详细技术方案 / 技术效果 / 相关附图）；
3. **内置通用模板** `assets/default-disclosure-template.md`。

> 复刻样稿时，**只复刻体裁与版面，不复刻其语言质量**。用户明确要求"比样稿写得更好"时，按第 4 节语言红线执行。

### 两种常见体裁对照

| 维度 | 机构交底书式 | 申请书/初稿式（如 fyr 初稿） |
|---|---|---|
| 章节 | 【发明名称】【所属技术领域】【背景技术介绍】【解决的技术问题】【详细技术方案】【技术效果】【相关附图】 | 标题行；技术领域 / 背景技术 / 发明内容 / 有益效果 / 附图说明 / 具体实施方式 |
| 语气 | 说明性，可含"待补充"提问 | 法定书面语，步骤用"本发明提供…，包括以下步骤：" |
| 步骤 | 可编号为 S1…Sn 并分条 | 段落式，每段以"；"结尾，句内自足 |
| 优点段 | 或为独立章节 | "有益效果"用"其一…；其二…；其三…" |
| 实施例 | 单独章节，含参数与结果 | "具体实施方式"，长段落，逐段引用"参考附图N" |
| 客体强化 | 需要在技术问题段完成 | 由"发明内容"的技术方案段完成 |

**选择规则**：用户给了样稿 → 按样稿；用户给了机构模板 → 按机构模板（可用样稿式语言写内部段落，但章节不改）；两者都无 → 默认模板。
若用户既给模板又要求"像某初稿那样排版"，**以用户的这句要求为准**（本次案件即如此）。

## 2. 版面约定

- 标题：独立成行、居中、加粗；发明名称 ≤25 字，不含"新型""改进""研究"。
- 章节标题：不编号或按用户样稿的编号方式；加粗、独立成行。
- 正文段落：首行缩进 2 字符、两端对齐、宋体 10.5pt（五号）；专利正文一律**短段承接**，避免超过约 15 行的整块文字。
- 公式：**独立成行、居中、按行文顺序连续编号**（(1)(2)(3)…），编号右对齐或置于式后括号内；
  **每个公式之后必须紧跟"其中，…表示…"的符号定义句**，同一符号全文同形、与符号表一致。
  > 常见错误：把后写的公式编号插到前文公式之前（如 (6) 出现在 (2) 之前）。定稿前按出现顺序通扫一遍编号。
- 符号表 / 参数表：紧接相关章节；参数须给"含义 + 实施例取值 + 可配置性说明"，只给最优值会限缩保护范围。
- 附图：只在"附图说明"中给出"图N为…"的句式，与正文引用编号一致；用户不要求绘制时**不画图**，仅在文末或附注列出待绘清单。
- 引用编号：沿用用户样稿的体例（如〔1〕〔2〕 或 [1][2]），不混用。
- 引证须可核验：期刊文献给"作者-年-刊名-卷期"，专利给公开号；**不得生成推测性的 DOI 或 URL**——无法核验的链接宁缺勿错，改标「〔待核验〕」并在文中说明由代理师补全。
- 现有技术若只拿到标题/摘要（如无法解析的 PDF），只按标题与公开号作限定引证，并显式标注「待核实」，禁止据此补写方案细节（编写现有技术同样受"不编造"约束）。

## 3. Word 生成与校验（DSH 离线路径）

本机通常无 pandoc / LibreOffice / python-docx，使用技能自带工具（纯标准库）：

```bash
python <skill>/tools/md_to_docx_min.py  <in.md>  <out.docx>      # md → A4 docx
python <skill>/tools/extract_docx_text.py <out.docx> <check.txt> # 回读校验
```

`md_to_docx_min.py` 支持的书写约定：

| 写法 | 渲染结果 |
|---|---|
| `# 标题` | 居中、黑体 18pt |
| `## / ### / ####` | 加粗小节标题（黑体 16 / 14 / 12pt） |
| `$$公式$$`（独立成行） | 居中公式段，无首行缩进 |
| `**粗体**` | 加粗 run |
| `_{下标}` / `^{上标}` | 真正的下标 / 上标（专利公式必需） |
| `\| 表格 \|` | 带边框表格，首行加粗 |
| 普通行 | 宋体 10.5pt、两端对齐、首行缩进 2 字符 |

**必做**：生成后用 `extract_docx_text.py` 回读一遍，确认段落数、公式与表格未丢失；`.md` 与 `.docx` 同时间戳成对交付。

## 4. 语言质量红线（"比样稿更好"的具体含义）

- 不出现营销腔与论文腔：**禁**"极大地""真正实现了""赋能/底座/闭环生态""本文/我们/笔者认为""首次""领先/SOTA"。
- 优点段必须是**因果句**：因（技术特征）→ 果（技术效果）→ 证据（数据/机理），而不是形容词堆叠。
- 每个步骤段落写清四件事：**处理对象、处理条件、处理结果、作用**；缺一项即视为公开不充分。
- 同一对象全文同一名称（如"岗位—任务二分网络"不得中途改称"双模网络"）；英文首次出现给全称+缩写。
- 公式与文字互为注脚：正文先给自然语言说明，再给公式，再给符号定义，最后给该式的技术含义。
- 样稿中的语病、公式串行、重复句一律**不继承**。
