# 交底书章节结构

与 `assets/default-disclosure-template.md` 对齐；用户模板优先。

```
1. 注意事项
2. 一、背景与现有技术
   - 1.1 现有技术（分类 + URL + 消化概括）
   - 1.2 现有技术缺点
3. 二、本发明要解决的技术问题
4. 三、技术方案详细阐述
   - 3.1 背景
   - 3.2 系统框图（mermaid）
   - 3.3 模块功能说明
   - 3.4 系统流程（mermaid）
   - 3.4.1 符号与公式（按需）
   - 3.5 关键技术参数表
5. 四、相对现有技术的优点
6. 五、技术关键点与欲保护点
7. 六、其它（实施例、效果、相关申请）
```

## 1.1 硬性要求

- 按**技术方向**分类，非文献堆砌
- 每条：标识、要点、场景、局限、**可核验 URL**
- 国知局 `abstract` 非空时，概括须与摘要一致（消化后重写）

## 语言

- 客观陈述：「为……，本方案……」「其中，……表示……」
- 避免：「并不只是……而是……」、论文腔、答辩腔
- 术语全文统一；英文首次出现：`中文（English Name, Abbr）`

## 公式

- 先引入句 → 公式 → 「其中，……表示……」
- 3.5 参数表「符号」列与 3.4.1 同形

## 文档头

```markdown
# 技术交底书
**案件名称**：……
**技术联系人**：……
**专利类型**：发明
```

## 命名与交付

完整规则见 **`references/delivery-naming.md`**：`{案件名}_{YYYYMMDDHHmmss}.md` / `.docx`，凡交付必双格式、必时间戳、禁止默认覆盖。
