# 脱敏成稿要求

交底书正文须**脱敏**：便于对外流转与代理人撰写，同时保留技术可实施性。成稿前与 `references/disclosure-checklist.md` 一并核对。

## 脱敏对照表

| 类型 | 脱敏方式 | 示例 |
|------|----------|------|
| 业务/行业 | 抽象为通用描述 | 「XX 质检」→「多标签分类场景」 |
| 具体分类 | 用字母类替代 | 「类别 1、类别 2」→「分类 A、分类 B、分类 C」 |
| 具体数值 | 范围或示例说明 | 「每日 5000 人」→「每日一定规模」 |
| 公司/产品 | 不出现具体名称 | 删除或替换为「某系统」「某平台」 |
| 客户/项目代号 | 不出现 | 替换为「某应用场景」 |
| 个人姓名/工号 | 文头联系人可占位「待填写」 | 正文不出现真实身份 |

## 脱敏检查表（完稿前）

| 检查项 | 要求 |
|--------|------|
| 业务/行业名称 | 已抽象为通用描述 |
| 具体分类标签 | 已用 A/B/C 等替代 |
| 具体数值 | 已用范围或「预设值」「典型值」等 |
| 公司/产品名 | 已删除或「某系统」 |
| 内部路径/仓库名 | 正文不出现 |

## 与忠实原文的关系

- **convert / draft**：从源材料提取技术方案时保留技术逻辑；**成稿交付前**对商业敏感标识脱敏
- **不得**为脱敏而删除关键技术步骤或参数关系；必要时用「预设阈值」「典型取值范围」保留可实施性
- 用户明确要求保留原名时，在对话中确认授权后再保留

## 交付正文禁忌

- **禁止**在交底书文末加入技能仓库、示例路径、「教学示例」「不构成法律承诺」等**元脚注**
- 固定免责声明仅出现在**对话说明**中，不写入 `.md`/`.docx` 正文（除非用户明确要求）

## 引用材料时的脱敏

扫描项目文档、设计稿、PPT 时：记录引用路径供内部核对，交底书中用脱敏表述（「参见某设计文档中的模块划分」），不写内部文件名或仓库路径。
